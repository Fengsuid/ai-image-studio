## 1. 参考资料

- Carbon Data Table：<https://carbondesignsystem.com/components/data-table/usage/>
- Carbon Filtering：<https://carbondesignsystem.com/patterns/filtering/>
- Material Design Data Tables：<https://m1.material.io/components/data-tables.html>
- PatternFly Bulk Select：<https://www.patternfly.org/component-groups/controls/bulk-select/>
- W3C WCAG 2.2：<https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/>

参考结论：

- 管理后台的数据表应该有明确标题、工具栏、搜索、筛选、排序、分页、行级动作、批量动作和详情展开/侧栏。
- 多条件筛选在数据量大或请求慢时，适合“先选条件，再应用”的 batch filter，避免每改一个条件就刷新。
- 批量操作要让用户清楚知道“选中了当前页、全部结果还是部分结果”。
- 面向运营/管理员的界面应少装饰、多密度、强扫描能力。

## 2. 当前前端与后台现状

### 2.1 前台页面

当前主要视图：

- `homeView`：首屏 hero、今日生成数、最近创作、灵感示例。
- `chatView`：文生图对话、生成状态、历史列表、底部 composer。
- `libraryView`：提示词库 + 广场作品混合展示。
- `editorView`：图生图画布、工具栏、提示词条、公开开关。
- `myWorks`：弹窗式作品管理，已有筛选 tab。

现状问题：

- 首页更像“生成入口 + 最近作品”，还不是“创作工作台首页”。
- 内容卡片的信息密度不一致：有些卡片强调图片，有些强调提示词，有些强调公开状态。
- 作品、提示词、广场、我的资产之间的关系不够清楚，用户需要自己理解“去生成 / 图生图 / 复制提示词 / 编辑标签”的区别。
- 空状态、加载状态、失败状态还偏临时 toast，不够稳定。
- 移动端导航和长页面操作仍依赖顶部导航 + 抽屉，常用入口可以更近。

### 2.2 管理员页面

当前 `openAdminModal()` 是弹窗，包含：

- 接口配置：API Key、Base URL、模型、积分、注册开关、版本信息。
- 用户表：角色、状态、积分、增减积分。
- 标签库管理：另一个弹窗，支持新增、编辑、隐藏、合并。
- 提示词管理：散落在提示词库卡片和详情弹窗里。

现状问题：

- 后台不是独立工作台，而是一个大弹窗。信息一多就会拥挤。
- 设置、用户、标签、提示词、公开作品管理分散，管理员没有一个总览。
- 用户表缺搜索、筛选、分页、批量启用/禁用、批量加积分。
- 标签合并还用 `prompt()`，无法预览影响范围。
- 生成请求、失败率、公开审核、举报、操作日志、系统健康都没有统一入口。
- 管理员改 API Key / 积分 / 用户权限时没有二次确认和审计视图。

## 3. 前台内容展示优化设计

### 3.1 首页升级为“创作控制台”

目标：用户打开首页后，不只看到 hero，而是立刻知道自己能继续做什么。

建议布局：

```text
┌─ 顶部导航 ───────────────────────────────┐
│ Image Studio    提示词库  广场  我的作品 │
├─ 主创作区 ───────────────────────────────┤
│ 大输入框 + 模型/尺寸/公开开关             │
│ [最近一次会话继续] [新建文生图] [上传图编辑]│
├─ 今日状态 ───────────────────────────────┤
│ 积分余额  今日生成  已公开  待继续会话     │
├─ 继续创作 ───────────────────────────────┤
│ 最近 3 个会话卡片：封面、标题、轮数、最后时间│
├─ 灵感/广场精选 ──────────────────────────┤
│ 分类 tab：推荐 / 风景 / 人像 / 产品 / 海报 │
└──────────────────────────────────────────┘
```

新增功能：

- `继续上次会话` 卡：显示最后一张图、轮数、最后 prompt 摘要。
- `我的草稿`：保存未提交 prompt、图生图未完成画布。
- `快捷动作`：文生图、图生图、查看我的公开作品、签到。
- `系统状态提示`：API Key 未配置、积分不足、注册待审核，显示在入口旁，不用等提交才 toast。

验收：

- 登录用户首页首屏能看到“继续创作”和“新建创作”两个入口。
- 未登录用户仍然有清晰的注册/登录入口。
- API 未配置时，生成按钮禁用并展示明确原因。

### 3.2 卡片体系统一

目标：提示词卡、广场作品卡、我的作品卡都有同一套信息层级，用户一眼看懂“这是什么、来自谁、能做什么”。

统一结构：

```text
┌─ 图片区 ─────────────────────┐
│ 封面图                         │
│ 左上：文生图/图生图/提示词       │
│ 右上：作者 / 已公开 / 私有       │
│ 底部：轮数 / 尺寸 / 模型         │
├─ 文本区 ─────────────────────┤
│ 标题或 prompt 摘要              │
│ 标签 chip                      │
│ 生成时间 / 收藏数 / 使用次数     │
├─ 操作区 ─────────────────────┤
│ [去生成] [图生图] [复制] [更多]  │
└──────────────────────────────┘
```

规则：

- 卡片图片永远是主角，文字不压在图片主体上。
- 操作按钮最多 3 个常驻，其他进 `更多`。
- 文生图和图生图用固定 icon + 文案，不只靠颜色区分。
- 长 prompt 默认两行截断，详情页再完整展示。
- 标签最多显示 3 个，超出显示 `+N`。

验收：

- 提示词库、广场、我的作品三处卡片看起来像同一套产品。
- 用户不打开详情也能知道作品类型、作者、公开状态。

### 3.3 作品详情页升级

目标：详情页从“大图预览”升级为“作品解释页”。

桌面布局：

```text
┌─ 主图/对比区 ─────────────┬─ 信息侧栏 ──────────────┐
│ 结果图                     │ 标题 / 作者 / 类型       │
│ 图生图时可切：结果 / 原图 / 对比│ prompt / 标签 / 模型    │
│                            │ 创作路线 / 来源 / 时间    │
│                            │ 操作：文生图 / 图生图 / 下载│
└───────────────────────────┴───────────────────────┘
```

新增功能：

- 图生图详情默认显示 `输入图 / 输出图` 对比模式。
- 文生图详情显示 `prompt 摘要 + 完整 prompt 展开`。
- 多轮作品显示“最终封面 + 路线缩略图”，路线可切换主图。
- 增加 `相关作品`：同作者、同标签、同 prompt 相似。
- 增加 `使用这个风格`：只带风格标签，不带原 prompt。

验收：

- 图生图作品不用读 prompt，也能看懂修改前后。
- 用户从详情页能明确选择：复用 prompt、基于图片编辑、下载、举报/管理。

### 3.4 “我的作品”升级为资产库

目标：从弹窗式列表变成可管理资产的正式页面或全屏抽屉。

建议入口：

- `/works` 或 `我的作品` 全屏 view。

信息架构：

```text
我的作品
├─ 全部
├─ 已公开
├─ 私有
├─ 文生图
├─ 图生图
├─ 草稿
└─ 已归档
```

功能：

- 搜索 prompt / 标签 / 日期。
- 网格视图与表格视图切换。
- 批量选择：公开、取消公开、归档、删除本地记录。
- 收藏 / 置顶。
- 收藏夹或项目集：例如“头像”“海报”“产品图”。
- 每张图的 `管理` 面板显示：公开状态、标签、原图、线路、下载版本。

验收：

- 用户能在 10 秒内找到一张旧图。
- 批量取消公开不需要逐张点详情。
- 删除历史和取消公开的含义在 UI 中清楚区分。

### 3.5 提示词库内容运营化

目标：提示词库不只是静态卡片，而是可浏览、可复用、可学习的内容区。

新增模块：

- `主题集合`：如“头像”“产品海报”“风景摄影”“电商主图”。
- `提示词拆解`：把 prompt 分成主体、风格、光线、镜头、构图、限制。
- `一键替换变量`：例如 `[主体]`、`[颜色]`、`[场景]`。
- `使用次数 / 收藏数 / 最近更新`。
- `相关推荐`：同标签、同风格、同用途。

卡片改进：

- 卡片正面放结果图 + 简短标题。
- 详情页放完整 prompt、变量字段、参考结果、适用场景。
- 管理员可以给提示词设置“推荐”“新手友好”“高级”标记。

验收：

- 新用户能从提示词库直接改变量生成，而不是复制一大段再手动找位置。
- 管理员能把优质提示词做成集合，而不是只能靠排序。

### 3.6 空状态、加载状态、失败状态

当前很多失败靠 toast，建议把关键状态固定在页面内。

场景：

- 没有历史作品：展示示例 prompt + 上传入口。
- 没有公开作品：解释公开到广场的好处 + 按钮。
- 提示词库加载失败：显示重试按钮 + 使用本地缓存状态。
- 图片加载失败：卡片里显示占位 + 重新加载。
- 生成失败：保留 prompt、参数、源图，给出重试和复制错误。

验收：

- 用户不会因为 toast 消失而不知道下一步。
- 图片失败不会造成空白卡片或布局塌陷。

### 3.7 移动端导航与常用入口

建议：

- 移动端加底部导航：`生成 / 广场 / 作品 / 编辑 / 我的`。
- 对话列表作为底部 sheet，而不是左侧抽屉缩到屏幕外。
- 生成 composer 底部固定，但展开参数时不遮挡输入框。
- 广场详情底部固定主操作：`文生图`、`图生图`、`下载`。

验收：

- 手机端单手能打开对话列表、提交生成、进入我的作品。
- 底部固定区域不遮挡图片主体和 prompt。

### 3.8 首次公开奖励与 12 小时撤回机制

目标：鼓励用户把优质作品分享到广场，同时避免“公开领积分后立刻撤回”的刷分行为。

核心规则：

- 每个用户只有一次“首次公开作品奖励”资格。
- 奖励触发条件是用户第一次把图片公开到广场，但积分建议采用“待入账”机制：
  - 公开成功后立即弹窗提示“首发奖励已锁定”。
  - 作品公开满 12 小时且未被用户撤回、未被管理员隐藏、未被审核拒绝后，奖励正式入账。
  - 如果平台不启用审核，则以 `publishedAt + 12h` 为到账时间。
- 用户公开作品后，只能在 12 小时内自主撤回。
- 超过 12 小时后，作品进入“长期公开”状态，用户不能直接撤回，只能：
  - 申请撤回。
  - 或由管理员在后台隐藏/下架。
- 管理员始终可以隐藏/下架任何公开作品，且不会受 12 小时限制。

用户侧弹窗：

```text
首次公开成功

你的作品已经进入广场。
首次公开奖励 +N 积分将在作品公开满 12 小时后入账。

你可以在 12 小时内撤回公开；撤回后本次奖励会取消。

[查看广场] [知道了]
```

撤回确认弹窗：

```text
撤回公开作品？

撤回后这张作品会从广场消失。
如果这是你的首次公开作品，待入账奖励也会取消。

剩余可撤回时间：07:26:18

[继续公开] [确认撤回]
```

超过 12 小时后的弹窗：

```text
已超过自主撤回时间

公开作品只支持在发布后的 12 小时内自主撤回。
如果你确实需要下架，可以提交撤回申请，管理员会处理。

[提交申请] [关闭]
```

前台展示：

- 我的作品卡片显示 `可撤回 08:12:33` 倒计时。
- 公开详情页如果是作者本人，显示撤回状态：
  - `12 小时内可撤回`
  - `已超过自主撤回时间`
  - `撤回申请处理中`
- 首次公开奖励在积分入口中显示为 `待入账 +N`。

反刷策略：

- 首发奖励只按用户维度发一次，不按作品发。
- 撤回、删除、管理员隐藏都会取消待入账奖励。
- 同一设备/IP 短时间注册多个账号公开作品，可以进入风控队列。
- 低质量空 prompt、重复图片、违规图片不触发奖励。

验收：

- 新用户首次公开作品能看到奖励弹窗和 12 小时到账说明。
- 12 小时内可以撤回，并且待入账奖励取消。
- 12 小时后普通用户不能直接撤回，只能申请。
- 管理员能看到这条奖励是否已入账、取消或待确认。

### 3.9 提示词点赞与热度

目标：让提示词库不只是管理员排序，也能通过用户反馈自然浮现好用内容。

前台功能：

- 提示词卡片显示点赞数，图标使用心形或拇指图标。
- 登录用户可以点赞/取消点赞提示词。
- 每个用户对同一提示词只能有一个有效点赞。
- 提示词详情显示：
  - 点赞数。
  - 使用次数。
  - 收藏/复制次数。
  - 最近更新时间。
- 提示词库排序新增：
  - 推荐。
  - 最新。
  - 最多点赞。
  - 最近热门。
  - 新手友好。

热度计算建议：

```text
hotScore =
  likeCount * 3
  + useCount * 2
  + copyCount
  - ageDecay
```

说明：

- `likeCount` 代表明确认可。
- `useCount` 代表实际转化。
- `copyCount` 代表学习价值。
- `ageDecay` 避免旧提示词永远霸榜。

UI 细节：

- 未登录用户点击点赞时，弹出登录弹窗，并说明“登录后可收藏和点赞提示词”。
- 点赞成功给轻量反馈，不全局刷新提示词库。
- 管理员隐藏提示词后，普通用户不可点赞。
- 管理员可以在提示词 CMS 里看到点赞用户数、使用次数和热度分。

验收：

- 同一用户重复点击只会点赞/取消，不会重复累计。
- 热门排序能反映点赞量变化。
- 管理员能查看高赞提示词和低赞提示词。

### 4.6.1 提示词重复治理与大模型审核接口

目标：解决提示词库里“语义重复、轻微改写、同模板换词、批量导入撞车”的问题，让管理员在发布前就能看到重复风险，而不是后续靠人工整理。

重复类型：

- 完全重复：prompt 文本一致或只差空格、标点、大小写。
- 近似重复：同一段 prompt 改了少量形容词、顺序或中英文标点。
- 语义重复：不同写法表达同一创作意图，例如“赛博朋克城市海报”和“霓虹未来都市宣传海报”。
- 模板重复：同一模板只替换了主体，如“生成一张{主体}电商主图”。
- 变体合理：同系列但用途不同，应保留为变体，例如同一个产品分别用于“海报 / 头像 / 电商详情页”。

建议采用四层审核架构：

```text
提交/导入提示词
  ↓
文本规范化 normalize
  ↓
确定性查重：hash / simhash / token overlap
  ↓
向量召回：embedding topK 相似候选
  ↓
大模型语义审核：判断 duplicate / variant / unique
  ↓
后台确认：合并 / 保留变体 / 退回草稿 / 强制发布
```

#### A. 规范化与确定性指纹

提交提示词时先生成规范化文本：

```text
normalize(prompt):
  - trim
  - 全角/半角归一
  - 英文 lower-case
  - 连续空白折叠
  - 去掉无意义标点
  - 中文标点统一
  - 常见同义词归一：photo/photography/摄影
  - 变量归一：{主体}、{{subject}}、[subject] → <subject>
```

保存字段：

- `normalized_prompt`
- `normalized_hash`
- `simhash`
- `token_count`
- `template_signature`

判定：

- `normalized_hash` 完全相同：直接 hard duplicate。
- `simhash` 汉明距离很小：高风险近似重复。
- `template_signature` 相同且变量位置一致：提示管理员“可能是模板变体”。

#### B. 向量召回

对以下内容拼接后生成 embedding：

```text
title + "\n" + prompt + "\n" + tags.join(",") + "\n" + source
```

查询流程：

- 新建/编辑提示词时，从已有 active/hidden prompts 中召回 top 10。
- 批量导入时先在导入批次内部查重，再与数据库查重。
- 召回结果只作为候选，不直接定罪。

建议阈值：

```text
similarity >= 0.94    高风险重复，默认阻止直接发布
0.86 - 0.94           进入大模型审核
0.78 - 0.86           只提示可能相似，不阻止
< 0.78                不展示
```

阈值要在后台设置里可调，并按中文/英文/混合 prompt 分开统计误判率。

#### C. 大模型审核接口

大模型不做最终裁决，只给结构化建议。最终动作仍由系统规则和管理员决定。

接口草案：

```text
POST /api/admin/prompts/audit-duplicate
```

请求：

```json
{
  "mode": "single",
  "draft": {
    "id": null,
    "title": "赛博朋克城市海报",
    "prompt": "...",
    "tags": ["poster", "cyberpunk"]
  },
  "candidates": [
    {
      "id": 12,
      "title": "霓虹未来都市宣传海报",
      "prompt": "...",
      "tags": ["poster", "city"]
    }
  ]
}
```

返回：

```json
{
  "decision": "duplicate",
  "confidence": 0.91,
  "duplicateOf": 12,
  "reason": "两条提示词都要求生成霓虹未来都市海报，主体、风格、用途高度一致。",
  "differences": ["新提示词强调赛博朋克，旧提示词强调未来都市"],
  "recommendedAction": "merge_as_variant",
  "canonicalTitle": "霓虹赛博朋克城市海报",
  "mergedTags": ["poster", "cyberpunk", "city"],
  "riskFlags": ["same_use_case", "same_visual_style"]
}
```

`decision` 枚举：

- `duplicate`：重复，建议合并或拒绝发布。
- `variant`：合理变体，可归入同一集合。
- `unique`：不重复。
- `needs_human_review`：模型不确定，交给管理员。

`recommendedAction` 枚举：

- `block_publish`
- `merge_as_variant`
- `keep_but_link_related`
- `publish_unique`
- `needs_manual_review`

模型提示词约束：

```text
你是提示词库审核助手。你的任务是判断 draft 是否与 candidates 重复。
只返回 JSON，不要返回 Markdown。
不要因为主题相近就直接判重复，要区分“同一用途重复”和“同系列合理变体”。
优先保护已有高质量提示词，避免发布低质量重复条目。
如果无法判断，返回 needs_human_review。
```

安全与成本：

- 每次只把 top 5-10 候选发给模型，避免 token 过大。
- prompt 内容超过上限时先摘要，再审核摘要 + 关键片段。
- 对 `normalized_hash + candidates ids` 做缓存，重复导入不重复调用模型。
- 设置 15-30 秒超时；超时后降级为“规则查重 + 人工审核”。
- 大模型审核结果写入数据库，保留模型名、版本、耗时、token/cost、原始 JSON 摘要。

#### D. 后台交互

在提示词编辑器右侧增加“重复检查”面板：

```text
重复检查
├─ 状态：高风险重复 / 可能相似 / 未发现重复
├─ 最高相似：91%
├─ 候选 1：霓虹未来都市宣传海报

├─ 候选 2：...

```

对比弹窗：

- 左：草稿提示词。
- 右：候选提示词。
- 高亮相同主体、风格、用途、镜头、颜色。
- 显示标签差异。
- 显示历史数据：候选点赞数、使用次数、发布时间、是否推荐。

批量导入时：

- 导入前生成重复报告。
- 每行显示：
  - `可导入`
  - `与库内重复`
  - `批次内重复`
  - `建议合并为变体`
  - `需要人工审核`
- 管理员可以批量选择“跳过重复项”“合并变体”“全部转草稿”。

#### E. 发布策略

建议状态机：

```text
draft
  ↓ duplicate check passed
active

draft
  ↓ duplicate risk high
needs_review
  ↓ admin approve
active
  ↓ admin reject
hidden / archived
```

规则：

- 普通管理员可以强制发布，但必须填写原因。
- 强制发布要写 audit log。
- 如果重复的是高赞提示词，默认不允许直接覆盖，只能创建 variant。
- 如果新提示词质量明显更高，可以把旧提示词设为 `superseded`，并把流量导向新提示词。

#### F. 误判处理

大模型审核一定会有误判，所以要设计“纠错”入口：

- 管理员可标记“误判为重复”。
- 管理员可标记“漏判重复”。
- 每次纠错写入 `prompt_audit_feedback`。
- 之后调整阈值、同义词表、模板签名规则时用这些反馈作为样本。

验收：

- 完全重复 prompt 无法直接发布。
- 轻微改写 prompt 会被提示高风险重复。
- 合理变体不会被硬拦截，而是建议归入集合。
- 批量导入 100 条提示词时能输出重复报告。
- 管理员强制发布重复提示词必须填写理由并写入审计日志。

```text
│  ├─ 超时撤回是否允许申请
│  └─ 举报阈值
├─ 存储与图片
│  ├─ 最大上传大小
│  ├─ 是否生成缩略图
│  └─ 是否清理元数据
└─ 运维
   ├─ 版本
   ├─ 超时
   └─ smoke test 状态
```

验收：

- 管理员改 API Key 后可以点“测试连接”。
- 改模型时能看到哪些前端能力会受影响。
- 危险设置保存前有 diff 确认。
- 首次公开奖励、撤回窗口、撤回申请开关都能在后台配置并显示当前生效值。

## 5. 后台页面通用组件规范

### 5.1 表格工具栏

每个列表页都应有：

- 标题和一句说明。
- 搜索框。
- 筛选入口。
- 排序。
- 刷新按钮。
- 导出按钮。
- 主操作按钮。

批量选择后，工具栏切换为：

```text
已选择 12 项    [取消选择] [批量隐藏] [批量改标签] [导出]
```

### 5.2 筛选模式

- 用户列表：即时筛选即可。
- 生成请求、广场审核：使用 batch filter，选完条件后点“应用筛选”。
- 所有筛选都要显示 active filter chips，可单独移除。
- 一键 `清除全部筛选`。

### 5.3 详情侧栏

行点击不直接执行动作，而是打开右侧详情 drawer：

- 顶部：对象名 + 状态 + 主操作。
- 中部：详情字段。
- 底部：危险动作。

好处：

- 不打断列表筛选上下文。
- 适合处理审核、用户、生成请求这些需要查看上下文的对象。

### 5.4 空状态和 loading

- 表格首次加载使用 skeleton，不只用 spinner。
- 筛选无结果时展示“清除筛选”。
- 接口失败时展示“重试 / 复制错误 / 查看状态”。

## 7. 实施路线

### P0：不改后端，先做后台壳和信息架构

- `/admin` 独立页面 shell。
- 左侧导航 + 顶部标题 + 内容区。
- 把现有设置、用户表、标签管理、提示词管理迁入后台 tab。
- 用户表增加前端搜索、筛选、分页视觉，数据仍用现有接口。
- 标签合并从 `prompt()` 改成弹窗。
- 后台总览先用现有 `/api/stats/today`、`/api/version`、`/api/admin/users` 拼出基础卡片。

验收：

- 管理员不再在大弹窗里操作后台。
- 所有现有后台功能都能从 `/admin` 找到。

### P1：管理列表能力补齐

- 后端用户列表支持搜索、状态筛选、分页。
- 公开作品后台列表。
- 公开作品增加 12 小时撤回状态、撤回申请列表。
- 提示词 CMS 列表 + 编辑器 + 恢复 hidden + 点赞量展示。
- 提示词确定性查重：`normalized_hash`、`simhash`、批量导入内部重复报告。
- 生成请求列表读取 `generation_requests`。
- 用户详情 drawer + 积分流水 + 首发奖励状态。
- 前台提示词点赞/取消点赞。

验收：

- 管理员能搜索用户、查看公开作品、查失败请求、查看首发奖励状态。
- 用户能给提示词点赞，提示词库能按点赞/热门排序。
- 管理员新建提示词时能看到完全重复和近似重复提醒。

### P2：审核、举报、审计

- 广场审核队列。
- 举报入口与后台举报处理。
- 审计日志。
- 批量操作。
- 危险动作二次确认。
- 首次公开奖励入账任务。
- 用户超过 12 小时后的撤回申请审批。
- 奖励取消、补发、回收写入审计。
- 向量召回 + 大模型重复审核接口。
- 提示词重复审核队列、候选对比弹窗、强制发布理由。

验收：

- 内容治理不需要直接进数据库。
- 关键管理员动作都有记录。
- 首发奖励不会被公开/撤回反复刷取。
- 批量导入提示词前能得到重复/变体/唯一的结构化报告。

### P3：运营与增长

- 首页创作控制台。
- 我的作品资产库。
- 提示词集合与变量。
- 重复提示词合并为变体、旧提示词 superseded 流量迁移。
- 用户等级、勋章、贡献榜。
- 高赞提示词榜单和优质创作者榜单。
- RUM 指标进后台。
- Provider capability preview。

验收：

- 普通用户前台从“能生成”升级为“能管理创作资产”。
- 管理员后台从“能配置”升级为“能运营”。
- 平台能通过奖励、点赞、榜单自然引导用户公开优质内容。

## 8. 验收清单

前台：

- 首页能继续会话、新建生成、进入图生图。
- 卡片类型、作者、状态、标签、主操作层级统一。
- 我的作品可以搜索、筛选、批量操作。
- 提示词库支持集合和变量。
- 提示词库支持点赞、取消点赞、按点赞/热门排序。
- 图生图详情能看到输入图/输出图对比。
- 用户首次公开作品能看到奖励弹窗、待入账积分和 12 小时撤回倒计时。
- 公开超过 12 小时后，用户不能直接撤回，只能提交撤回申请。

后台：

- `/admin` 是独立页面，不再依赖一个大弹窗承载所有功能。
- 用户、作品、提示词、标签、生成请求都有独立入口。
- 所有表格都有搜索、筛选、排序、分页、批量动作。
- 每个重要对象都有详情 drawer。
- 危险动作有二次确认和审计记录。
- 后台总览能显示系统健康、生成量、失败率、待处理内容。
- 用户详情能显示首发奖励状态、待入账积分、撤回记录和点赞行为。
- 广场审核能处理撤回申请、奖励取消和 12 小时窗口外的作品下架。
- 提示词 CMS 能显示点赞量、使用量、热度分，并能识别异常点赞。
- 提示词 CMS 能在发布前识别重复、近似重复和合理变体。
- 大模型审核结果必须可解释、可覆盖、可审计，不能黑盒决定是否发布。
