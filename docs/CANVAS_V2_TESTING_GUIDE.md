# Canvas v2 功能测试指南

本文面向开发者和 agent，提供 Canvas v2 画布功能的分层测试方法。目标是让每次改动都有可重复的验证步骤，而不是凭感觉说"应该没问题"。

## 1. 测试原则

1. 先测最简单的（能打开），再测复杂的（能生成）。
2. 先测不依赖真实 AI 的流程，再测真实生成。
3. 每次改动只验证一个变量，不要同时改 UI、数据和生成逻辑。
4. 失败时记录：URL、操作步骤、控制台错误、网络请求。
5. smoke 脚本能覆盖的不要手工测，手工测试只覆盖交互体验。

## 2. 测试环境准备

### 2.1 本地环境

```bash
npm install
cp .env.example .env
# 填入 MySQL 连接信息和管理员账号
npm start
```

确认服务正常：

```bash
curl http://localhost:3000/api/health
# 期望返回 JSON，包含 csrf token
```

### 2.2 Canvas v2 构建

```bash
npm run canvas:v2:build
```

确认构建产物存在：

```bash
ls public/canvas-v2/index.html
ls public/canvas-v2/assets/main.*.js
```

### 2.3 测试账号

- 使用 `.env` 中配置的管理员账号登录。
- 或通过后台创建测试用户。
- 确认测试用户有足够积分（或配置免费生成）。

## 3. 第一层：Smoke 测试（自动化）

已有脚本覆盖基础可用性，每次部署后必须执行：

```bash
npm run smoke:canvas-v2:static   # 静态资源返回 200
npm run smoke:canvas-v2:entry    # /canvas-v2 入口可访问
```

### 自定义 smoke 扩展

如果需要测试完整 CRUD 链路，可运行：

```bash
node scripts/smoke/check-canvas-v2.mjs http://localhost:3000
```

该脚本应覆盖：

| 检查项 | 预期 |
| --- | --- |
| `GET /canvas-v2` | 返回 200，HTML 包含 `data-canvas-v2-root` |
| `GET /canvas-v2/assets/main.*.js` | 返回 200，Content-Type 含 javascript |
| 未登录访问 `POST /api/canvases` | 返回 401 或 403 |
| 登录后 `POST /api/canvases` | 返回 200，body 含 canvas id |
| `GET /api/canvases/:id` | 返回 200，body 含 dataJson |
| `PATCH /api/canvases/:id` | 返回 200 |
| `DELETE /api/canvases/:id` | 返回 200 |
| 导出 `GET /api/canvases/:id/export` | JSON schema 为 `ai-image-studio.canvas.v1` |

## 4. 第二层：项目 CRUD 测试（手工）

目标：确认画布项目的创建、保存、恢复、删除都正常。

### 测试步骤

1. 打开 `/canvas-v2`，确认项目列表加载。
2. 点击新建画布，确认进入编辑器。
3. 添加一个文本节点，输入内容。
4. 等待自动保存（观察保存状态指示）。
5. 刷新页面，确认节点仍存在。
6. 在另一个浏览器/隐身窗口登录同一账号，打开同一画布，确认内容一致。
7. 回到项目列表，重命名画布。
8. 删除画布，确认列表中消失。

### 预期结果

- 新建后立即可编辑，不需要额外操作。
- 自动保存在编辑后 1-2 秒内触发。
- 刷新后所有节点位置、内容、连线完整恢复。
- 删除后不可再通过 URL 直接访问。

### 失败信号

- 新建后白屏或报错。
- 刷新后节点丢失。
- 保存状态一直显示"保存中"不结束。
- 删除后仍能打开画布。

## 5. 第三层：节点编辑交互测试

目标：确认画布核心编辑体验稳定。

### 5.1 节点操作

| 操作 | 步骤 | 预期 |
| --- | --- | --- |
| 创建节点 | 从侧边栏拖入或点击添加 | 节点出现在视口中心或指定位置 |
| 拖动节点 | 鼠标按住节点拖动 | 节点跟随鼠标，释放后位置保持 |
| 缩放节点 | 拖动节点边角 | 节点尺寸变化，内容自适应 |
| 删除节点 | 选中后按 Delete 或点删除按钮 | 节点消失，相关连线同步消失 |
| 复制粘贴 | Ctrl+C / Ctrl+V | 新节点出现在原节点附近，内容相同 |
| 框选 | 在空白处拖动框选 | 框内节点被选中，高亮显示 |

### 5.2 连线操作

| 操作 | 步骤 | 预期 |
| --- | --- | --- |
| 创建连线 | 从节点输出端口拖到另一节点输入端口 | 连线出现，两端正确连接 |
| 删除连线 | 选中连线后删除 | 连线消失，节点不受影响 |
| 环路检测 | 尝试创建形成环路的连线 | 连线被拒绝或给出提示 |

### 5.3 视口操作

| 操作 | 步骤 | 预期 |
| --- | --- | --- |
| 平移画布 | 在空白处拖动 | 画布跟随移动 |
| 缩放画布 | 滚轮缩放 | 画布缩放，节点大小相应变化 |
| 小地图导航 | 点击小地图位置 | 视口跳转到对应区域 |
| 重置视图 | 点击重置按钮 | 视口回到默认位置和缩放 |

### 5.4 重点观察

- 100 个节点时拖动是否卡顿。
- 缩放后节点交互热区是否准确。
- 删除节点后是否有残留连线。
- 复制后的节点 ID 是否唯一。
- 保存后刷新，所有位置和连线是否完整恢复。

## 6. 第四层：生成链路测试

目标：确认从画布触发图片生成的完整链路。

### 6.1 前置条件

- 后台已配置至少一个可用的 AI 供应商。
- 测试用户有足够积分。
- 或者配置 mock 供应商用于测试。

### 6.2 文生图测试

步骤：

1. 创建 prompt 节点，输入提示词。
2. 创建 config 节点，选择模型和尺寸。
3. 创建 output 节点。
4. 连线：prompt → config → output。
5. 在 output 节点点击"生成"。
6. 等待生成完成。

预期：

- 生成中显示 loading 状态。
- 成功后 output 节点显示生成的图片。
- 图片 URL 是服务端路径（如 `/api/images/:id/file`），不是 blob 或 data URL。
- 用户积分被正确扣除。

### 6.3 图生图测试

步骤：

1. 创建 image 节点（上传或引用一张图片）。
2. 创建 prompt 节点，输入编辑指令。
3. 创建 config 节点。
4. 创建 output 节点。
5. 连线：image + prompt → config → output。
6. 触发生成。

预期：

- 后端识别为图生图请求。
- 生成结果基于参考图。
- 参考图 URL 有效（不是 blob/data）。

### 6.4 失败场景测试

| 场景 | 预期行为 |
| --- | --- |
| 供应商未配置 | 明确错误提示，不是空白或 500 |
| 积分不足 | 提示积分不足，不扣费 |
| 上游 API 超时 | 显示超时错误，节点状态可恢复 |
| 网络断开 | 显示网络错误，不丢失已有数据 |
| prompt 为空 | 提示需要输入内容 |

### 6.5 生成后验证

- 生成记录是否写入 `generations` 表。
- `canvas_generation_links` 是否正确关联。
- 生成的图片是否可在画廊中查看（如果设为公开）。
- 刷新画布后生成结果是否仍显示。

## 7. 第五层：入口切换测试（Phase 5）

目标：确认从其他页面进入 Canvas v2 的链路。

### 7.1 从首页生成结果进入

步骤：

1. 在首页生成一张图片。
2. 点击"加入画布"。
3. 确认跳转到 Canvas v2。
4. 确认画布中出现对应的 image 节点和 prompt 节点。

### 7.2 从画廊详情进入

步骤：

1. 打开画廊中一个作品详情。
2. 点击"用此线路新建画布"。
3. 确认创建新画布并包含对应节点。

### 7.3 从提示词库进入

步骤：

1. 打开提示词库。
2. 选择一个提示词，点击"加入画布"。
3. 确认画布中出现 prompt 节点。

### 7.4 回滚测试

步骤：

1. 设置 `CANVAS_ENTRY_MODE=legacy`，重启服务。
2. 确认画布入口指向旧画布。
3. 设置 `CANVAS_ENTRY_MODE=hidden`，重启服务。
4. 确认画布入口不可见。
5. 恢复 `CANVAS_ENTRY_MODE=v2`。

## 8. 第六层：数据完整性测试

目标：确认画布数据在各种操作后保持一致。

### 8.1 导入导出往返

1. 创建一个包含多种节点和连线的画布。
2. 导出为 JSON。
3. 检查 JSON schema 为 `ai-image-studio.canvas.v1`。
4. 删除画布。
5. 新建画布并导入刚才的 JSON。
6. 确认所有节点、连线、位置完整恢复。

### 8.2 数据清洗验证

- 导出的 JSON 中不应包含 `data:` 或 `blob:` 图片 URL。
- 节点坐标和尺寸应为有限数字。
- 节点 ID 应唯一。
- 边的 source/target 应指向存在的节点。

### 8.3 并发保存

1. 快速连续操作（拖动多个节点）。
2. 确认 debounce 保存不会丢失中间状态。
3. 刷新后最终状态正确。

## 9. 性能基准

| 场景 | 可接受标准 |
| --- | --- |
| 空画布首次加载 | < 2 秒 |
| 50 个节点拖动 | 无明显卡顿 |
| 100 个节点拖动 | 可接受轻微延迟，不卡死 |
| 保存 100 节点画布 | < 3 秒 |
| 项目列表加载 50 个画布 | < 2 秒 |

## 12. 常见问题排查

| 现象 | 可能原因 | 排查方式 |
| --- | --- | --- |
| `/canvas-v2` 返回 404 | 构建产物不存在 | 检查 `public/canvas-v2/index.html` |
| 白屏无内容 | JS 加载失败 | 浏览器控制台查看网络错误 |
| 登录后仍提示未登录 | CSRF token 问题 | 检查 cookie 中是否有 `csrf` |
| 保存失败 | session 过期或 CSRF 失效 | 刷新页面重新登录 |
| 生成返回 500 | 供应商配置错误 | 检查后台供应商面板和服务器日志 |
| 节点位置错乱 | 视口变换计算错误 | 检查 viewport 数据是否正确保存 |
| 图片不显示 | URL 路径错误或文件不存在 | 检查 imageUrl 是否为有效服务端路径 |
